# sigilix-glyphs

Pre-rendered SVG badge assets for the [Sigilix](https://sigilix.ai) PR-review bot.

This repo exists for one reason: GitHub's `js-gh-image-fallback` client-side script injects `border-radius: 6px` + `background-color: var(--bgColor-muted)` onto every `<img>` it considers a "user-supplied external image" — including everything proxied through `camo.githubusercontent.com`. The only hosts that bypass Camo are `*.githubusercontent.com` URLs (verified empirically via `gh api /markdown` on 2026-05-26). Serving the glyphs from a **public** GitHub repo via `raw.githubusercontent.com` is the cleanest path to sharp corners + reliable loading.

## URL pattern

```
https://raw.githubusercontent.com/Sigilix/sigilix-glyphs/<tag>/<name>.svg
```

Tag = the glyph asset version (e.g. `v20260527-1`). Use the immutable tag, never `main`, so GitHub's image cache busts deterministically when we bump.

## Glyphs

Priority (20×20 filled square):

- `p0.svg` — critical / merge-blocker (red)
- `p1.svg` — high (orange)
- `p2.svg` — medium (lime)
- `p3.svg` — low / nit (slate)

Category (20px-tall pill, width proportional to label):

- `logic.svg`, `security.svg`, `performance.svg`, `error-handling.svg`, `testing.svg`, `complexity.svg`, `style.svg`, `syntax.svg`, `docs.svg`

## Updating

The glyphs are generated by the Sigilix repo's `scripts/generate-static-badges.ts` from the runtime `BADGE_SVGS` table in `src/lib/badge-assets.ts`. Workflow:

1. Edit visual properties in `Sigilix/sigilix` → `src/lib/badge-assets.ts` (or whichever colors / glyph paths)
2. Bump `BADGE_ASSET_VERSION` in that file (e.g. `v20260527-1` → `v20260528-1`)
3. Run `pnpm tsx scripts/generate-static-badges.ts` — outputs to `assets/badges/<new-version>/`
4. Mirror the new SVGs to **this** repo (copy + commit + tag with the new version)
5. Push the new tag — `git push origin v20260528-1`
6. Now `raw.githubusercontent.com/Sigilix/sigilix-glyphs/v20260528-1/p0.svg` resolves
